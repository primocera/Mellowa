# MW-V12-07 · Measure real-user performance instead of only warm local speed

- **Run after:** MW-V12-06
- **Primary risk removed:** Warm local LCP is strong, but cold-start LCP was approximately 4.08s and INP has not been measured.

## Prompt

Improve Mellowa performance evidence and remove avoidable first-visit latency without sacrificing safety or accessibility.

Inspect:
- current perf Playwright project and vitals artifacts
- Next.js bundle output and route boundaries
- server/client component splits
- font loading decisions
- API waterfalls on landing, pricing, signup and first authenticated view
- current production analytics/privacy registry

Required implementation:
1. Keep lab budgets for LCP and CLS, but label lab, warm-server and cold-start results separately.
2. Add a repeatable cold-start measurement against a deployed preview or production-like environment.
3. Do not call a click-to-paint proxy INP.
4. Add privacy-safe real-user Web Vitals collection for LCP, CLS and INP if the current consent/analytics model allows it.
5. Collect route, device class and build ID only. Do not collect check-in text, wellbeing data, plan content, email or user ID.
6. Define minimum sample sizes and percentile reporting before using field results for a launch claim.
7. Profile and fix avoidable critical-path work:
   - unused JS/CSS/fonts;
   - unnecessary client components;
   - blocking third-party code;
   - serial data requests;
   - oversized landing payloads.
8. Preserve accessibility, visible content without JavaScript where intended and reduced-motion behavior.
9. Add performance regression budgets to the release workflow without making a single flaky cold run the only gate.

Output:
- before/after transfer size and route metrics;
- separate warm, cold and field status;
- remaining hosting-level limitation;
- exact statement allowed in launch docs.
